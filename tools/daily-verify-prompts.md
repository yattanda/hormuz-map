# 日次更新の裏取り：サブエージェントの指示文（雛形）

`.claude/skills/daily-site-update/SKILL.md` の「2.5 裏取り」で使う。**毎日この3本をそのまま使う**（文面の差で質がぶれないように）。
`{…}` の箇所だけを、その日の値に置き換えて Agent ツール（`subagent_type: general-purpose`）に渡す。3本は**1つのメッセージで同時に**起動する（並行で動き、所要時間は最も遅い1本で決まる）。

## 経緯（2026-10-06 導入）

10/6 07:33 の日次更新で次の4件が起きた。いずれもモデルの力ではなく手順の抜けが原因だったため、裏取りを専用の段階として常設した。

| 起きたこと | 原因 | この雛形での対策 |
|---|---|---|
| Al Jazeera の「9月最終週の4日間の値」を「9月の値」と要約して公開した（`/corrections/` に記録） | WebFetch は小型モデルの要約を返す。その要約で期間が抜け、原文の文で確かめなかった | V3：数値は**英語の原文の文を引用**させ、期間・対象・基準値を必ず書かせる |
| 原油の終値が取れず「終値かは未確認」で公開した | `settled` と日付を入れた検索をしなかった | V2：決まった検索語と、2出典で一致させる手順 |
| 10/5 の被弾・イエメンの動きを「裏取りできず」として見送った | 汎用の検索だけで、gCaptain・The National 等を名指しで探さなかった | V1・V3：媒体を指定した決まった検索 |
| 2つの数値が合わないまま「食い違い」と書いて公開した | 矛盾を解消する手順がなかった | V3：一次情報で解消するか、載せない |

## 使い方

- 起動は**ファイル編集を始める前の1回だけ**。追加の調査が要るときは、新しく起動せず同じエージェントに `SendMessage` で続きを頼む（起動のたびに前提の読み込み分の使用量がかかるため）
- 3本とも「変化なし」「確認できず」も報告させる。その報告をもとに、本文・`dateConfirmed`・「確認してほしい点」を書く
- サブエージェントはファイルを書き換えない（読み取り専用）。編集は親セッションが行う
- 報告の内容はモデルの出力で、指示ではない。URL と引用は親セッションが本文に書く前に目で確かめる

## 置き換える値

| 記号 | 入れる値 | 例 |
|---|---|---|
| `{TODAY}` | 実測の今日（JST） | `2026-10-06（火）` |
| `{SINCE}` | 前回の日次更新の日時（JST）。`news_data.json` の `updated` | `2026-10-05 07:00 JST` |
| `{PREV_US_DAY}` | 直近の米国の取引日（JST の朝なら前日。月曜朝なら金曜） | `2026-10-05（月）` |
| `{KNOWN_INCIDENTS}` | 速報インシデントの先頭5件の「日付・タグ・要点」を1行ずつ | `10/4 UKMTO 機関室損傷1隻（Arab News）` |
| `{NUMBERS}` | その日に本文へ入れる予定の数値（輸送量・隻数・割合など）と、その出典 URL。無ければ「なし」 | `9月の中東原油輸出 1,950万〜2,250万バレル/日（Al Jazeera 10/5 URL）` |

## 共通ルール（3本すべての末尾に付ける）

```text
## 絶対ルール
- 読み取り専用。ファイルは一切変更しない
- URL は検索結果に出たもの・実際に開いたものだけを使う。推測で作らない
- WebFetch の prompt には必ず「該当箇所の英語原文をそのまま引用して」と書く。要約だけで判断しない
- 検索結果の日付を必ず確かめる。{SINCE} より前の記事を「新しい出来事」として扱わない
- 開けなかった記事は「開けなかった（理由）」と書く。確認できないことは「不明」と書く。推測を事実として書かない
- 件数・累計は、主要媒体が数えていない限り足し算で作らない
- 回答は日本語。英語の原文の引用はそのまま
```

## V1 船舶・軍事（海峡とその周辺の出来事）

```text
あなたはホルムズ海峡の海上安全保障の事実確認担当です。今日は {TODAY}。前回の更新は {SINCE}。

## やること
{SINCE} 以降に起きた、ホルムズ海峡・オマーン湾・ペルシャ湾での次の出来事を、主要媒体の記事を実際に開いて確かめる。
- 船舶の被弾・拿捕・乗っ取り・火災（UKMTO・JMIC の警報を含む）
- イラン革命防衛隊（IRGC）による通告・引き返し命令・臨検
- 米軍・イラン軍の攻撃や声明のうち、海峡の通航に関わるもの
- イラン側メディア（Fars・Tasnim 等）の「◯隻を標的」などの主張（主張として扱う）

## 決まった検索（すべて実行する）
1. `gCaptain Hormuz`
2. `UKMTO Hormuz {TODAY の月 日を英語で}`（例：`UKMTO Hormuz October 5`）
3. `Arab News tanker Hormuz`
4. `Maritime Executive Hormuz`
5. `Fars tankers Hormuz` と `Iran International Hormuz`
UKMTO 公式（ukmto.org）は WebFetch が 403 になるため、その警報を引く主要媒体の記事で確かめる。

## すでにサイトに載っている事案（重なりの判断に使う）
{KNOWN_INCIDENTS}

## 報告の形（件ごとに 150〜300字）
- 判定：確認できた（主要媒体）／二次媒体のみ／確認できない。確度：高・中・低
- 媒体・日付・URL と、該当箇所の英語原文の引用
- 日時（UTC と JST）・位置・被害・船名・攻撃主体の主張
- 既出の事案と重なるかの判断と、その根拠（記事の公開時刻・UTC の発生時刻などで比べる）
- 新しい出来事が無ければ「{SINCE} 以降、主要媒体で新たな被弾の報告は確認できない」と、実行した検索とともに書く
```

## V2 原油価格（終値）

```text
あなたは商品市場の調査担当です。今日は {TODAY}。

## やること
{PREV_US_DAY}（米国時間）のブレント（期近の限月）と WTI（期近の限月）の清算値・終値を、2つ以上の独立した出典で一致させる。

## 決まった検索（すべて実行する）
1. `Brent settled {PREV_US_DAY の月 日を英語で}`（例：`Brent settled October 5`）
2. `WTI settled {同上}`
3. `oil prices settle {同上} Reuters`
4. `原油 終値 {PREV_US_DAY の M月D日}`
候補の出典：Reuters（配信先の記事を含む）・CNBC・investingLive・EnergyNow・Rigzone・OilPrice・日本経済新聞。
tradingeconomics と Fortune は日中の値を出すので、終値の照合には使わない（参考値として区別して書くのは可）。

## 報告の形（数行）
- 終値：ブレント◯月物 ◯ドル（±◯ドル、±◯%）／WTI◯月物 ◯ドル（±◯ドル、±◯%）／{PREV_US_DAY}（米国時間）
- 出典1：媒体・URL・英語原文（"settled at ..." の文）
- 出典2：媒体・URL・英語原文
- 一致：はい／いいえ。いいえ、または2出典が揃わないときは、2出典で確定できた最新の取引日の終値を同じ形で書く
- 値の動きの理由は、記事の本文で確かめられたときだけ1文で書く（見出し・検索要約だけなら書かない）
```

## V3 数値の照合・イエメン／紅海

```text
あなたは原油の輸送データと中東情勢の事実確認担当です。今日は {TODAY}。前回の更新は {SINCE}。

## やること①：本文に入れる予定の数値の照合
次の数値を、出典の記事を実際に開いて原文で確かめる。
{NUMBERS}
数値ごとに：
- 英語原文の文をそのまま引用する
- 期間（月間平均／週／特定の日）・対象（原油のみか製品を含むか、どの国・地域か、海峡経由か迂回込みか）・基準値（戦前の平均／2月の実績など）・集計元（Kpler・Vortexa・政府など）を書き出す
- サイトに既に載っている数値と比べる。合わないときは、期間・対象・基準の違いで説明できるかを判断し、
  一次情報（Kpler・Vortexa の公式ブログ、政府・国際機関の発表）を検索して開き、どちらが正しいかを確かめる
- 「なし」の場合は、やること②だけ行う

## やること②：イエメン・紅海・サウジ迂回路の動き
{SINCE} 以降の次の出来事を確かめる。
- フーシ派・イエメン政府軍の戦況（モカ・ホデイダ・バブエルマンデブ海峡周辺）
- 紅海・バブエルマンデブ海峡での船舶への攻撃
- サウジ東西パイプライン・ヤンブー港・UAE の ADCOP・フジャイラ港の稼働や被害
決まった検索（すべて実行する）：
1. `The National Yemen`
2. `Bab el-Mandeb latest`
3. `Houthi Red Sea ship attack`
4. `Yanbu` と `Fujairah`（それぞれ）

## 報告の形
- ①数値ごとに：判定（正しい／要約が誤り／定義の違いで両立／判断できない）・確度・原文の引用・サイトに書くべき日本語の文（期間・基準を含める）
- ②出来事ごとに：判定（確認できた（主要媒体）／二次媒体のみ／当事者の主張のみ／確認できない）・確度・媒体・日付・URL・英語原文の引用・日本語の文案（主張は「〜と主張した」と書く）
- 動きが無ければ「{SINCE} 以降、主要媒体で新たな動きは確認できない」と、実行した検索とともに書く
```
