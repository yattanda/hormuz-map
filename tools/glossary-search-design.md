## 2. 設計ポリシー（提案）

| # | ポリシー | 理由 |
|---|---|---|
| P1 | **日次更新の書き手（クラウドの日次スキル）に新しい作業を足さない** | 日次は毎朝 `docs/index.html` を直接書く。本文に用語のタグを手で入れる方式にすると、型が1つ増え、`validate_daily.py` の検査も増える |
| P2 | **用語の正本は1か所（`glossary.json`）** | ツールチップの短い説明・用語集ページ・検索の同義語を、同じデータから出す。食い違いが起きない |
| P3 | **用語集ページは静的 HTML で出す**（JS 描画にしない） | 検索エンジンと JS 無効の環境で読める。`PROJECT_CONTEXT` §6 の「主要な内容は HTML にテキストとして持つ」と同じ考え方 |
| P4 | **外部ライブラリ・外部送信・Cookie・ローカルストレージを足さない** | `/privacy/` 第4〜6章の改訂が要らない範囲に収める。TBT が支配的な現状（Performance 26）を悪化させない |
| P5 | **JS が動かなくても本文は今のまま読める**（用語の印が付かないだけ） | 付加機能が壊れても本体を巻き込まない |
| P6 | **スマホ・キーボードでも同じことができる** | スマホに「マウスオーバー」は無い。タップと Tab キーで同じ操作を用意する |
| P7 | **定義文は編集コンテンツとして扱う** | 出典を付け、推測を事実として書かない。誤りは `/corrections/` の対象 |
| P8 | **パスの変更（③）と機能追加を同じ PR に混ぜない** | 不具合が出たときの原因を切り分けられるようにする（`redesign-plan` §0 の大原則と同じ） |

## 3. 機能A：用語集とツールチップ

### 3-1. 構成

```
docs/data/glossary.json        ← 正本（運営者が確認した定義文）
        │
        ├─ tools/build_glossary.py ──→ docs/glossary/index.html（静的 HTML・用語ごとに id）
        │
        └─ docs/assets/glossary.js ──→ 各ページで本文中の用語に印を付け、ポップアップを出す
```

### 3-2. データ（`docs/data/glossary.json`）

1用語あたりの項目（名前は詳細設計で確定）：

| 項目 | 内容 | 例 |
|---|---|---|
| `id` | 英数字とハイフン。用語集ページのアンカーになる | `irgc` |
| `term` | 見出しの表記 | `IRGC（イスラム革命防衛隊）` |
| `match` | 本文中で印を付ける文字列（複数可） | `["IRGC", "革命防衛隊"]` |
| `reading` | よみ（用語集ページの並び順） | `あいあーるじーしー` |
| `short` | ツールチップ用の短い説明。**60字前後・1〜2文** | — |
| `body` | 用語集ページ用の説明（数段落） | — |
| `category` | 分類 | 組織／地名・施設／原油・市場／船舶・海運／軍事／このサイトの用語 |
| `sources` | 出典（表示名と URL。URL は検索で確認したものだけ） | — |
| `related` | 関連用語の `id` | `["centcom"]` |
| `updated` | 定義文を変えた日 | `2026-10-xx` |

### 3-3. 用語集ページ（`/glossary/`）

- 置き場所：`docs/glossary/index.html`（法務ページと同じディレクトリ形式・CRLF・BOM なし）
- URL：`https://chokepointlab.com/glossary/`。**ルート直下に置く**。
  理由：パナマ運河・津軽海峡など他の海峡でも使う用語があり、媒体全体の資産になる。③ でトップが `/hormuz/` に移っても URL が変わらない
- 中身：分類ごとの見出し → 用語（`<dt id="term-irgc">`／`<dd>`）。冒頭に分類の目次。各用語に出典・関連用語・
  「この用語を含む日次記録を見る」（機能B の検索結果へのリンク）
- 生成：`tools/build_glossary.py` が `glossary.json` から書き出す。一時ファイル → `os.replace()`、dry-run 既定、
  終了コードで成否（CLAUDE.md のスクリプトの節どおり）
- 構造化データ：`DefinedTermSet`／`DefinedTerm`（JSON-LD）。確度：中（リッチリザルトの対象ではないが、用語と定義の対応を機械に伝える）
- 付随：sitemap に1行、フッターから1リンク、GA4 タグ（J3「全ページ」の方針どおり）、`canonical`・`og:url` は絶対 URL

### 3-4. ツールチップの動き

| 操作 | 動き |
|---|---|
| 用語にカーソルを乗せる | 用語の上（収まらなければ下）に短い説明が出る |
| カーソルを外す | 消える。**ただしポップアップの中へ移した場合は消さない**（中を押せるようにするため。消すまで約0.15秒の猶予を置く） |
| ポップアップの中を押す | `/glossary/#term-<id>` へ移る（同じタブ） |
| スマホ：用語をタップ | 出る。ポップアップの中をタップで用語集へ。外をタップで消える |
| キーボード：Tab で用語へ | 出る。Enter で用語集へ。Esc で消える |

- ポップアップは画面に1個だけ（`<body>` 直下に1要素を作り、位置を計算して使い回す）。画面端では左右にずらす。幅は `min(320px, 100vw - 24px)`
- 見た目：用語には点線の下線だけ（色は変えない。リンクの青と区別する）。ポップアップは既存のトークン（`tools/design-system.md`）で組む
- WCAG 2.1 の 1.4.13（ホバーで出る内容は、消せる・乗れる・勝手に消えない）を満たす形にする

### 3-5. 用語に印を付ける方法（**自動・表示時**）

`glossary.js` が読み込み後に、指定した範囲の本文テキストを走査し、`match` に当たった箇所を
`<a class="gl-term" href="…/glossary/#term-<id>">` で包む。本文の HTML ファイルは書き換えない（P1）。

| 決めること | 基本設計での方針 |
|---|---|
| 印を付ける範囲 | ページごとに**対象の区域を明示**する（許可リスト方式）。トップなら 速報インシデント・ルート表・シナリオ・ニュース・更新履歴 など。区域の id は詳細設計で列挙 |
| 付けない場所 | リンク（`<a>`）の中・ボタン・見出し・地図・ティッカー・入力欄・`<script>`／`<style>`・TradingView の埋め込み |
| 頻度 | **1区域につき各用語の最初の1回だけ**。IRGC はニュース JSON に123回出るので、全部に付けると下線だらけになる |
| 長い語を優先 | 「産油国共同備蓄」と「備蓄」が両方ある場合は長い方 |
| JS が後から描く部分 | ニュース（`news_data.json`）・アーカイブは描画のあとに `Glossary.annotate(要素)` を呼ぶ。`MutationObserver` での常時監視はしない（処理が読めなくなるため） |
| 負荷 | 用語を1本の正規表現にまとめ、`requestIdleCallback` で初期描画の後に実行。`glossary.json` は遅延読み込み（見込み 15〜25KB） |

### 3-6. 共通ファイルの置き場所

- `docs/assets/glossary.js`（CSS も同じファイルから `<style>` として差し込むか、`glossary.css` を別に置くかは詳細設計）
- 各ページは `<script defer src="…/assets/glossary.js">` の1行で読み込む
- 【注意】CLAUDE.md の「`docs/index.html` 1ファイルに HTML・CSS・JS を集約」から外れる最初の共通 JS になる（→ 判断事項 U2）

## 4. 機能B：日次アーカイブのキーワード検索（第1段階）

### 4-1. 画面

- `/archive/` の「月別で見る／フェーズ別で見る」の上に検索欄を1つ置く
- 入力すると第3のビュー「検索結果」に切り替わり、**全期間**から該当する日を新しい順に並べる。上に「◯件（◯日分）」
- 各結果は今の日別カードと同じ形。該当語を `<mark>` で強調。カードから「この月の一覧で見る」（`#d-YYYY-MM-DD`）へ移れる
- 入力を消すと元のビュー（月別／フェーズ別）に戻る。0件のときは「見つかりません」と表記ゆれの例を出す

### 4-2. 検索の方法

| 項目 | 方針 |
|---|---|
| 対象データ | すでに読み込んでいる `archive_timeline.json` の `summary`・`dateLabel`・`relatedNews[].title`／`sourceLabel` |
| 方式 | ブラウザ内の部分一致。**索引もライブラリも作らない**（173件・約4万字なので全件走査で足りる。見込み1ms 未満・確度：高） |
| 表記のゆれ | 全角・半角と大文字・小文字を同一視（NFKC＋小文字化）。「ＩＲＧＣ」「irgc」でも当たる |
| 複数語 | 空白区切りで AND（「機雷 CENTCOM」＝両方を含む日） |
| 同義語 | **`glossary.json` の `match` を使って広げる**（「米中央軍」で「CENTCOM」の日も当たる）。機能A が無くても検索は動く。あれば賢くなる |
| 日本語入力 | 変換中（IME の確定前）は検索しない。確定後 約0.15秒で実行 |
| URL | `/archive/?q=機雷` で同じ結果を開ける（用語集ページからのリンク・共有用）。既存の `#2026-07` と併用できる |

### 4-3. 第2段階以降（今回は設計しない。判断の材料だけ）

| 候補 | 件数（実測） | 所見 |
|---|---|---|
| ニュース・OSINT のアーカイブ（`news_data.json`） | OSINT 101件＋過去分104回分・398KB | 記録系なので日次アーカイブの検索と相性がよい。**広げるならここが先** |
| 退避した速報インシデント（`incident_archive.json`） | 193件・258KB | E1 で「ページからはリンクしない」と決めたデータ。検索で出すなら、その決定を変えることになる（要判断） |

| サイト全体（法務ページ等を含む全文検索） | — | **必要性は低い**とみる。全文検索の索引はビルド工程（Pagefind 等）が要り、`docs/` をそのまま配信する現在の構成に合わない |

## 7. 判断していただきたい点

**【2026-10-02 決定】U1〜U7 はすべて「推奨」の列のとおり（運営者）。**

| # | 論点 | 推奨 | ほかの案 |
|---|---|---|---|
| U1 | 用語の印付け | **表示時に JS が自動で付ける**（P1） | 本文に手でタグを書く：確実だが日次の型と検査が増える |
| U2 | 共通 JS を `docs/assets/` に置く（「1ファイル集約」からの初の例外） | **置く**。トップ・アーカイブ・記事で同じ部品を使うため | 各ページに同じコードを貼る：直すたびに7か所以上 |
| U3 | 用語集の URL | **`/glossary/`**（ルート直下・媒体共通） | `/hormuz/glossary/`：海峡ごとに分かれ、共通の用語が重複する |
| U4 | 検索語を GA4 に記録するか | **第1段階は記録しない**（`?q=` を付けても GA4 に流れない作りにできるかは詳細設計で実測。現時点では不明） | 記録する：需要が分かるが `/privacy/` 第6章の改訂と単独コミットが要る |

### 9-4. JS

**状態**：`CURRENT_QUERY`（空文字なら通常表示）。既存の `CURRENT_VIEW` はそのまま残し、検索を消したら元のビューに戻る。

**前処理（読み込み時に1回）**：各エントリーに検索用の文字列を持たせる。

```js
const norm = s => String(s || '').normalize('NFKC').toLowerCase();
// 対象：summary・dateLabel・relatedNews の title と sourceLabel・日付（"2026-09-14" と "2026年9月14日"）
e._hay = norm([e.summary, e.dateLabel, e.date, fmtJpDate(e.date),
               ...(e.relatedNews || []).flatMap(n => [n.title, n.sourceLabel])].join('\n'));
```

**検索**：

```js
function parseQuery(raw){                       // 空白区切り・重複除去・最大5語
  return [...new Set(norm(raw).split(/\s+/).filter(Boolean))].slice(0, 5);
}
function search(terms){                         // AND・新しい順
  return ALL_ENTRIES.filter(e => terms.every(t => e._hay.includes(t)))
                    .sort((a, b) => a.date < b.date ? 1 : -1);
}
```

**強調**：正規化すると文字数が変わる（全角→半角など）ので、位置を写すのではなく、
元の文字列に当たる正規表現を語から作る。英数字は半角・全角の両方に当たる文字クラスにし、`iu` フラグで大文字・小文字を同一視する。
強調は「エスケープ前の文字列を正規表現で分割 → 各片を `escapeHtml` → 当たった片だけ `<mark>` で包む」の順で行う
（エスケープ後の HTML に正規表現をかけない）。強調できなかった場合もカード自体は出す。

**描画**：既存の `renderEntriesList(entries, opts)` に `opts.highlight`（正規表現）・`opts.noGap`（「◯日分の速報なし」を出さない）・
`opts.jump`（「この月の一覧で見る」を出す）を足して使い回す。月の区切りは出す（`showMonthDivider:true`）。

**表示の切り替え**：

| 状態 | 月タブ・フェーズタブ・フェーズの説明 | ビューのボタン | 件数の行 |
|---|---|---|---|
| 検索語なし | 今のまま | 今のまま | 隠す |
| 検索語あり | 隠す | どちらも選択なしの見た目 | 「『機雷』を含む記録：◯日分（全173日）」 |
| 0件 | 隠す | 同上 | 「見つかりません。表記を変えてお試しください（例：ゲシュム島／ケシュム島）」 |

- ビューのボタンを押す・× を押す・Esc → 検索語を消してそのビューに戻る
- 「この月の一覧で見る」→ 検索語を消し、月別ビューでその月を開き、`#d-YYYY-MM-DD` へスクロール

**入力**：`input` イベントから 150ms 後に実行。`compositionstart`〜`compositionend` の間（日本語の変換中）は実行しない。
`submit` は `preventDefault`（Enter でページを再読み込みしない）。

**URL**：読み込み時と `hashchange` で `#q=<語>` を読み、入力欄に入れて検索する（`decodeURIComponent`・失敗したら無視）。

**安全**：検索語は `textContent`／`escapeHtml` を通してから画面に出す（`#q=` に HTML を書かれても実行されない）。
正規表現に入れる前に記号をエスケープする。
