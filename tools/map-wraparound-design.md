## 1. 現状（2026-10-02 実測）

### 1-1. 何が繰り返され、何が繰り返されないか

| 要素 | 個数 | 横方向の繰り返し | 根拠 |
|---|---|---|---|
| 背景タイル（CARTO `dark_all`・`dark_only_labels`） | 2層 | **無限に繰り返す**（Leaflet の既定） | `docs/index.html:3307-3313`（`noWrap` 指定なし） |
| 国土ポリゴン（`countries.geojson`） | 元データ×3 | **±360° の2コピーだけ手で複製済み**（コピー側は `interactive:false` でツールチップなし） | `docs/index.html:3373-3397` |
| 印（マーカー・国名ラベル・海域名） | 82 | **1個だけ** | 実測（`map.eachLayer`） |
| 線（航路・パイプライン・運河） | 14 | **1本だけ** | 同上 |

印の経度は −98°（アメリカの国名ラベル）〜 210°（アラスカ。`[61.2, 210.0]` と 180° を超える値で書いてある）。

### 1-2. どこで切れるか（ズーム3・コンテナ 1223px・表示幅は経度で約215°）

| 地図の中心経度 | 見えている範囲 | 画面内の印 | 画面内の線 |
|---|---|---|---|
| 68°（初期表示） | −40〜175° | 72 | 11 |
| 180° | 72〜287° | 10 | 8 |
| 250° | 142〜357° | **1** | 1 |
| 300° | 192〜407° | **0** | 1 |
| 428°（＝68°＋360°。背景は初期表示と同じ絵） | 320〜535° | **0** | 0 |
| −292°（＝68°−360°） | −399〜−184° | **0** | 0 |

東へ1周すると、背景と国土は初期表示と同じ絵に戻るのに、印と線は1つも出ない。これが「コンテンツの左右が切れている」の正体。

ズーム2（世界1周＝1024px）ではコンテナ（1223px）のほうが広く、画面に世界が約1.2周ぶん並ぶ。背景は2回出るが、印は1回しか出ない。

### 1-3. 原因

Leaflet の仕様。タイルレイヤーだけが経度方向に折り返し、印・線・面は書かれた経度の1か所にしか描かれない（公式リファレンスの `worldCopyJump` の説明がこの前提で書かれている）。Leaflet 本体に「印を全コピーに出す」機能は無い（Issue #1945 は閉じられており、安定版 1.9.4 に該当機能は無い）。

## 2. 方式の比較

| 案 | 内容 | 途切れ | 規模 | 主な欠点 |
|---|---|---|---|---|
| A | `worldCopyJump: true` だけ | **継ぎ目で残る** | 1行 | 中心が ±180° をまたぐ瞬間に元の世界へ戻すだけなので、継ぎ目の反対側にある印は出ない（例：中心 170° で画面右端に来るはずのパナマ −80°） |
| **B（推奨）** | 印・線・面を ±360° に複製 ＋ `worldCopyJump` ＋ 中心経度の補正 | **なし**（試作で確認・§4） | JS 60〜100行 | DOM の印が3倍（82→246）。ポップアップの引き継ぎなど細部の作り込みが要る（§5） |
| C | MapLibre GL JS へ載せ替え | なし（線・面は全コピーに描画。印は見えているコピーへ自動で移る） | **地図コード全体の書き直し**（約1,000行・印80か所・凡例と地点ジャンプのコントロール・ペイン・ツールチップ） | 本体が大きい（v5 系で gzip 約275KB、Leaflet は約42KB）。WebGL 必須。日次更新・毎月4日タスクが触るポップアップの書き方が変わる。球体表示（globe）はこの案でだけ可能 |
| D | Leaflet 2.0 を待つ | 不明 | — | 2.0 は alpha のまま（npm の `latest` は 1.9.4、`alpha` は 2.0.0-alpha.1）。世界コピーへの重ね描きが入るという情報は確認できていない |
| E | 折り返し自体をやめる（`noWrap`＋`maxBounds`） | 途切れは消えるが回せなくなる | 数行 | 要望（一定方向に回し続けたい）と逆。アラスカ航路（経度 180° またぎ）が地図の端で切れる |

### B を推す理由

1. いまのライブラリのままで、要望（回しても途切れない）を満たすことを試作で確認できた
2. 印・線を書いている約80か所の書き方を変えないので、日次更新（`apply_diffs.py`・スキル）と毎月4日の石油備蓄タスクに影響しない
3. 外部の読み込み先が増えないので `/privacy/` の改訂が要らない
4. C（MapLibre）へ進む場合でも、B で足すのは独立した小さなコードで、捨てても損が小さい

### C（MapLibre）を今回は推さない理由と、検討すべき時期

- 載せ替えの費用が「エンドレス化」という目的に対して大きすぎる
- ただし **タイルの切り替え（上流の J1・未決。CARTO は商用に Enterprise ライセンスが必要で、期限は AdSense 申請の前）** で、切り替え先がベクタータイルになるなら、MapLibre が自然な選択になる。そのときは B のコードを捨てて C に寄せればよい
- 「地球儀のように」を文字どおりの球体表示にしたい場合は C だけが答えになる（§8 の未決1）

## 3. 基本設計（B 案）

### 3-1. 全体像

```
[既存の書き方のまま]  L.marker(...).addTo(map).bindPopup(...)
        │  map の 'layeradd' を拾う
        ▼
[自動複製]  経度 −360°・＋360° に同じ見た目・同じポップアップのコピーを足す
        ＋
[中心の補正]  中心経度が −180〜180° を出たら、360° ずらして戻す（絵は同じなので見た目は動かない）
```

コピーが覆う範囲は、中心が −180〜180° にある限り経度 −540〜540°。画面の表示幅が 720°（世界2周ぶん）以下なら、画面内のどこにも抜けが出ない。コンテナの最大幅は `.container` の `max-width:1400px`、最小ズーム2の世界1周は 1024px なので、最大でも約1.4周ぶんで収まる。

### 3-2. 自動複製（`layeradd` フック）

- `map.on('layeradd', ...)` で、追加されたレイヤーが **印（`L.Marker`）・線（`L.Polyline`）・面（`L.Polygon`）** のときだけ複製する。グループ（`L.GeoJSON` など）自体は複製しない（中の子が1つずつ `layeradd` を出す）
- 複製は `setTimeout(0)` で1拍遅らせる。既存コードは `.addTo(map).bindPopup(...)` の順で書いてあり、`layeradd` の時点ではまだポップアップが付いていないため
- コピーには目印（例：`layer._wrapOf = 元レイヤー`）を付け、コピーをさらに複製しない
- 元とコピーの3つを1組として持つ（例：`元._wrapSet = [左コピー, 元, 右コピー]`）。ポップアップの引き継ぎ（3-5）で使う
- 複製する中身
  - 印：座標の経度 ±360、`options`（アイコン・`interactive`・ペイン）を共有、ポップアップ・ツールチップは元の内容と設定を引き継ぐ。**コピーは `keyboard:false`**（Tab キーの停止位置を3倍にしない）
  - 線・面：全頂点の経度 ±360、`options`（色・破線・ペイン）を共有、ポップアップ・ツールチップを引き継ぐ
- fetch の完了後に足されるもの（`military.json`・湖・河川・国土）も同じフックで拾えるので、読み込み順を気にしなくてよい
- **既存の `addWrappedLayers`（`docs/index.html:3373-3397`）は撤去**し、国土もこの仕組みに一本化する。コピー側の国名ツールチップも効くようになる（いまはコピー側だけ効かない）

呼び出し側（印80か所・線14本）は**1文字も変えない**。これが日次更新と両立させる要点。

### 3-3. 中心経度の補正

- `L.map('map', { ..., worldCopyJump: true })` を初期化時に指定する（ドラッグ中に ±180° をまたいだ瞬間に 360° 戻す。Leaflet はこのオプションをドラッグ処理を最初に有効にするときにしか読まない（1.9.4 のソースで確認）ので、あとから `map.options` に入れても効かない。初期化時に指定する）
- ドラッグ以外（`flyTo`・キーボード・慣性スクロールの終点）のために、`moveend` で中心が −180〜180° を出ていたら `map.setView(map.wrapLatLng(center), zoom, {animate:false})` で戻す
- 補正の前後で画面の絵は同じ（コピーが同じ位置にあるため）

### 3-4. 地点ジャンプ（`flyTo`）の最短経路

いまは `map.flyTo([9.15, -79.88], 9)` のように書かれた経度へ飛ぶ。中心が 170° にあるときパナマ（−80°）へ飛ぶと、東回り110° ではなく西回り250° を飛ぶ。
`jumpMapTo()`・`jumpMapHome()` で、目標の経度を「いまの中心にいちばん近いコピー」に直してから飛ぶ。

```js
function nearestLng(lng, refLng) {
  return lng + 360 * Math.round((refLng - lng) / 360);
}
```

着いたあとは 3-3 の `moveend` 補正が中心を −180〜180° に戻す。

### 3-5. 開いているポップアップの引き継ぎ

中心を 360° 戻すと、開いていたポップアップは元の経度に残るので画面から消える。補正のとき、ポップアップの持ち主が複製の組（3-2）に入っていれば、**ずらした向きの隣のコピーで開き直す**。ツールチップはマウスを動かせば出直すので対応しない。
（詳細設計で、開き直すのではなく同じポップアップの位置を360°移す方式に変えた。§11-4）

### 3-6. `?focus=` と `focusOn()`

`FOCUS_TARGETS` は元の印を指し、`setView(marker.getLatLng())` は元の経度（−180〜180° の中）へ移るので、**変更不要**。

### 3-7. 経度の書き方の決まり

- 点は −180〜180° で書く
- 180° 線をまたぐ線は、いまのアラスカ航路のように**連続した値**（…170, 180, 190, 200, 210）で書く。−180 と 180 で折り返して書くと、線が地図を横切る
- アラスカの印（`[61.2, 210.0]`）は線の終点と合わせてあるのでこのままでよい（コピーは −150° と −510° に出す。§11-2）

### 3-8. ズームと印の縮尺

- 最小ズーム2は変えない。ズーム2では画面に世界が1周以上並ぶので、同じ印が2回見える（背景も2回見えているので、むしろ整合する）
- 印の縮小（`updateMarkerScale()`・`#map.mz-*`）はセレクタで全部の印に当たるので、コピーにもそのまま効く

## 4. 試作の計測結果（2026-10-02）

ブラウザ上で既存ページに 3-2・3-3 相当の処理を当てて測った（ソースは変えていない）。

### 4-1. 途切れの有無

中心経度を −180〜160° まで 20° 刻みで動かし、「理論上画面に入るはずの印の数」と「実際に画面内にある印の数」を比べた。

| ズーム | 世界1周 | 食い違い |
|---|---|---|
| 2 | 1024px（画面に約1.2周） | **0件／18地点** |
| 3 | 2048px | **0件／18地点** |
| 5 | 8192px | **0件／18地点** |

実際のドラッグ（東へ4回）でも、中心は 166° → −95° → 3° と折り返し、印と線は出続けた。

### 4-2. 重さ

| 項目 | 前 | 後 |
|---|---|---|
| 印の DOM 要素 | 82 | 246 |
| SVG のパス | 796 | 834 |
| 60回連続で動かす時間（3回計測） | 776〜1,108ms | 1,008〜1,250ms |

時間は計測ごとのばらつきと重なっており、差は「あっても2〜3割」としか言えない。描画時間の大半は国土ポリゴン（元から3倍）で、印と線の複製の寄与は小さい。**スマホ実機では未計測**（§7）。

## 6. 実施の順序と PR の分け方

- PR は2本に分ける（どちらも単独でマージできる）

| PR | 内容 | 見た目の変化 |

### 2 の補足：「2回見える」とは何か

最小ズーム2では世界1周が 1024px。地図の幅がそれより広い PC（地図の幅 1223px＝ウィンドウ幅 1280px のとき）では、画面に世界が約1.2周ぶん入る。
初期の中心（経度68°）なら、**西経147°〜77°の帯（北米の大半とパナマ運河）が、地図の左端と右端の両方に出る**。背景はいまでも両側に出ているが、B 案を入れると印・線・国名ラベルも両側に出る（例：「アメリカ」の国名ラベル、パナマ運河の印）。
スマホ・タブレット（地図の幅 1024px 以下）と、ズーム3以上では起きない。

| 案 | 重複 | 世界全体を一目で見られるか | 欠点 |
|---|---|---|---|
| (a) そのまま | 出る（幅 1024px 超・最小ズームのときだけ） | 見られる | 同じ印が左右に2つ見える |
| (b) PC の最小ズームを3 | 出ない | **見られない**（1223px で経度215°ぶん） | 「全体を見る」ができなくなる |
| **(c) 最小ズームを幅に合わせる** | **出ない** | **ちょうど1周ぶん見える** | 最小ズームのときだけ背景タイルが最大1.36倍に引き伸ばされ、地名の文字がわずかに甘くなる |

(c) は、最小ズームを `log2(地図の幅 ÷ 256)` にする（幅 1223px なら 2.26）。世界1周がちょうど地図の幅になる。幅 1024px 以下では従来どおり2。
試作では、最小ズームで表示幅がちょうど360°、ズームの段は 2.26 → 3 → 4（戻りも同じ）、途切れの食い違い0件だった（§12）。

### 11-2. 自動複製

```js
// ============================================================
// 1-B. WORLD WRAP（横方向エンドレス）
//    印・線・面を経度 ±360° に自動で複製する。呼び出し側は何も変えなくてよい。
//    設計：tools/map-wraparound-design.md
// ============================================================
const WORLD_INDEXES = [-1, 0, 1];   // 複製を置く世界（0 が経度 -180〜180°）

function shiftLatLngs(lls, d) {
  return lls.map(x => Array.isArray(x) ? shiftLatLngs(x, d) : L.latLng(x.lat, x.lng + d));
}
// その印・線が書かれている世界の番号。アラスカ（経度210°）は 1 になる
function wrapHomeIndex(layer) {
  const lng = layer instanceof L.Marker ? layer.getLatLng().lng : layer.getBounds().getCenter().lng;
  return Math.round(lng / 360);
}
function makeWrapCopy(src, d) {
  let c;
  if (src instanceof L.Marker) {
    const ll = src.getLatLng();
    // コピーは Tab キーの対象にしない（停止位置を3倍にしないため）
    c = L.marker([ll.lat, ll.lng + d], Object.assign({}, src.options, { keyboard: false }));
  } else if (src instanceof L.Polygon) {
    c = L.polygon(shiftLatLngs(src.getLatLngs(), d), src.options);
  } else {
    c = L.polyline(shiftLatLngs(src.getLatLngs(), d), src.options);
  }
  c._wrapOf = src;
  const p = src.getPopup(), t = src.getTooltip();
  if (p) c.bindPopup(p.getContent(), p.options);
  if (t) c.bindTooltip(t.getContent(), t.options);
  return c;
}
// 既存コードは .addTo(map).bindPopup(...) の順で書いてあり、layeradd の時点では
// まだポップアップが付いていない。複製は1拍おいてからまとめて行う
let wrapQueue = [];
function flushWrapQueue() {
  const q = wrapQueue; wrapQueue = [];
  q.forEach(src => {
    if (!map.hasLayer(src)) { delete src._wrapCopies; return; }
    const home = wrapHomeIndex(src);
    WORLD_INDEXES.filter(i => i !== home).forEach(i => {
      src._wrapCopies.push(makeWrapCopy(src, (i - home) * 360).addTo(map));
    });
  });
}
map.on('layeradd', e => {
  const src = e.layer;
  if (src._wrapOf || src._wrapCopies) return;                              // コピー自身・複製済み
  if (!(src instanceof L.Marker) && !(src instanceof L.Polyline)) return;  // L.Polygon は L.Polyline の派生
  src._wrapCopies = [];
  if (wrapQueue.push(src) === 1) setTimeout(flushWrapQueue, 0);
});
map.on('layerremove', e => {
  const cs = e.layer._wrapCopies;
  if (!cs) return;
  delete e.layer._wrapCopies;
  cs.forEach(c => map.removeLayer(c));
});
```

決めごと

- 複製の対象は `L.Marker` と `L.Polyline`（`L.Polygon` を含む）。グループ（`L.GeoJSON`）は対象にしない。中の子が1つずつ `layeradd` を出すので、子の単位で複製される
- 複製先は「世界 −1・0・1」の3つから、その印が書かれている世界を除いた2つ。アラスカの印（経度210°＝世界1）のコピーは −150° と −510° に出る。±360° 固定にすると 570° に出て、左側（−510°）が抜ける
- コピーのポップアップ・ツールチップは、複製した時点の内容と設定を写す。**あとから `setPopupContent()` で書き換える印を作る場合は、コピーにも反映する処理が要る**（いまはそういう印は無い）
- 印を消すとコピーも消える（`layerremove`）

### 11-3. 中心経度の補正と、ドラッグ中の描き直し

```js
// 中心が worlds×360° ずれたとき、開いているポップアップを同じ見た目の位置へ移す
let wrapOpenPopup = null;
map.on('popupopen',  e => { wrapOpenPopup = e.popup; });
map.on('popupclose', e => { if (wrapOpenPopup === e.popup) wrapOpenPopup = null; });
function carryPopup(worlds) {
  if (!wrapOpenPopup || !worlds) return;
  const ll = wrapOpenPopup.getLatLng();
  const ap = wrapOpenPopup.options.autoPan;
  wrapOpenPopup.options.autoPan = false;     // 位置を移すだけ。地図を動かさない
  wrapOpenPopup.setLatLng([ll.lat, ll.lng + worlds * 360]);
  wrapOpenPopup.options.autoPan = ap;
}

// ドラッグ中：worldCopyJump が中心を 360° 戻した瞬間を、中心経度の飛びで見つける
let wrapLastLng = map.getCenter().lng;
let wrapDragging = false;
map.on('dragstart', () => { wrapDragging = true; wrapLastLng = map.getCenter().lng; });
map.on('dragend',   () => { wrapDragging = false; });
map.on('drag', () => {
  const lng = map.getCenter().lng;
  const worlds = Math.round((lng - wrapLastLng) / 360);
  wrapLastLng = lng;
  if (!worlds) return;
  carryPopup(worlds);
  // 線・面（SVG）は moveend でしか描き直されない。戻した直後は SVG が画面の外に
  // 残るので、ここで描き直させる（無いと、指を離すまで線と国土が消える）
  map.fire('moveend');
});

// ドラッグ以外（flyTo・キーボード・慣性の終点）：止まった時点で中心を -180〜180° に戻す
map.on('moveend', () => {
  if (wrapDragging) return;                  // ドラッグ中は Leaflet の戻しに任せる（下の決めごと）
  const c = map.getCenter();
  const worlds = -Math.round(c.lng / 360);
  if (!worlds) return;
  map.setView([c.lat, c.lng + worlds * 360], map.getZoom(), { animate: false });
  carryPopup(worlds);
});

// worldCopyJump は「どこで戻すか」の基準を zoomend のときにしか計算し直さない。
// ズームを変えずに遠くへ移ると（上の補正・focusOn・キーボード）基準が古くなり、
// 戻す位置が ±180° からずれる。地図を置き直したら zoomend を出して計算し直させる
map.on('viewreset', () => map.fire('zoomend'));
```

決めごと

- **ドラッグ中は `moveend` の補正を止める**（`wrapDragging`）。ドラッグ中の描き直しで `moveend` を出すので、止めないと補正がドラッグの途中で `setView` を呼ぶことがある（Leaflet が戻した直後の中心が −180.3° のような値になり、補正が「範囲外」と判定する）。模擬テストで実際に起きた（§12-8）
- **`viewreset` で `zoomend` を出す**のは、Leaflet 1.9.4 の `worldCopyJump` の作り（ソースに `TODO refactor` とある）を補うため。無いと、遠くへ移ったあとのドラッグが ±180° で戻らず、中心が 192° まで進んだ（§12-8）。`zoomend` を聞いているサイト側の処理（`attachLeafletZoom()`：タンカーパネルのクラスと印の縮尺）は、同じズームで呼ばれても結果が変わらない

- ドラッグ中の「戻し」は Leaflet の `worldCopyJump` に任せ、自前のコードはその結果を見るだけにする。1回の `drag` イベントで中心が180°以上動くことは実際の操作では起きないので、飛びを「戻し」と判定してよい（ズーム2で 512px を1イベントで動かす必要がある）
- `map.fire('moveend')` をドラッグ中に呼ぶのは、Leaflet の公開 API だけで SVG を描き直させるため。`moveend` を聞いているのは Leaflet のタイル・描画と、上の補正だけ（サイト側に `moveend` のリスナーは無い。`zoomend` だけ）。**今後 `moveend` に処理を足すときは、ドラッグ中にも呼ばれることを前提にする**
- 慣性スクロールの途中は補正しない（Leaflet の内部変数を書き換える必要があるため）。代わりに、慣性で進む距離に上限を付けて、複製が覆っている範囲（経度 −540〜540°）の外が見えないようにする（§11-7）

### 11-7. 慣性スクロールの上限

指を離したあとの慣性は Leaflet が1本のアニメーションで動かすので、途中で中心を戻せない。
複製が覆うのは経度 −540〜540° で、離した時点の中心は −180〜180° にある。**慣性で進める距離を「世界1周の幅 − 地図の幅の半分」までに抑えれば、画面は必ず複製の範囲に収まる。**

```js
const WRAP_OVERHANG = 45;   // 線が自分の世界からはみ出してよい経度（アラスカ航路は 180° を 30° 越える）

// 慣性で進む距離の上限を、いまのズームと地図の幅から決める。
// Leaflet の慣性の距離は inertiaMaxSpeed² ÷ (2 × inertiaDeceleration × easeLinearity)
function limitInertia() {
  const o = map.options;
  const world = 256 * Math.pow(2, map.getZoom());
  const room = world - map.getSize().x / 2 - world * WRAP_OVERHANG / 360;
  o.inertiaMaxSpeed = Math.sqrt(Math.max(0, room) * 2 * o.inertiaDeceleration * o.easeLinearity);
}
limitInertia();
map.on('zoomend', limitInertia);
map.on('resize', limitInertia);
```

- Leaflet 1.9.4 のソース（`Map.Drag._onDragEnd`）で、慣性の距離は「指の速さ² ÷ 34,000」px（既定値のとき）と確認した。指の速さ 3,000px/秒で 265px、10,000px/秒で 2,941px。模擬テストの値と一致した（§12-7）
- 上限が効くのは引いたときだけ

| 地図の幅・ズーム | 慣性の上限 | 上限に当たる指の速さ |
|---|---|---|
| スマホ（365px）・ズーム2 | 714px（画面2枚ぶん弱） | 約4,900px/秒より速い |
| スマホ・ズーム3 | 1,610px | 約7,400px/秒より速い |
| スマホ・ズーム5以上 | 実質なし（10,000px/秒でも当たらない） | — |
| PC（1223px）・最小ズーム2.26 | 459px | 約3,900px/秒より速い |

- 速く弾いたときに、引いた状態では従来より手前で止まる。代わりに印が消える区間が無くなる
- `map.options.inertiaMaxSpeed` は Leaflet の公開オプション。Leaflet はドラッグを終えるたびに読むので、あとから書き換えて効く
