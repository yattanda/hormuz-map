# 石油備蓄コラム 月次追記手順

対象：`docs/articles/oil-stockpile-monthly-trend.html`（📉 石油備蓄はどう推移したか──月次まとめとグラフで見る現在地）
と、`docs/hormuz/index.html` の石油備蓄日数3か所（地図ポップアップ・精製所表の注記・主要指標の備蓄カード。2026-10-01〜）、
ハブ `docs/index.html` の「主要な数字」1か所（2026-10 の構造再編で追加）

毎月4日に、前月末時点の値を追記する。
速報は「◯日時点」の値が3日後に公表されるため（例：8月31日時点 → 9月3日公表）、月末当日には月末値がまだ無い。

## 1. データを取得する

- 一次資料：資源エネルギー庁「石油備蓄の状況（推計値の速報）」
  `https://www.enecho.meti.go.jp/statistics/petroleum_and_lpgas/pl001/pdf-oil-res/oil_daily.pdf`
- **curl / WebFetch では取得できない**（bot対策で 403 / 202 が返る）。
  アプリ内ブラウザ（`mcp__Claude_Browser__*`）で
  `https://www.enecho.meti.go.jp/statistics/petroleum_and_lpgas/pl001/` を開き、
  そのページ上で `fetch('/statistics/petroleum_and_lpgas/pl001/pdf-oil-res/oil_daily.pdf')` して、
  pdf.js（`cdn.jsdelivr.net/npm/pdfjs-dist`）でテキストを抽出する
  - **PDF の URL へはタブを移動させない。**アプリ内ブラウザは PDF を表示せずダウンロードしようとし、
    Windows の「名前を付けて保存」のダイアログが開いて人の操作待ちになる（2026-10-02・10-04 に発生）。
    開くのは pl001 の一覧ページだけにする
  - 開いた直後の fetch は 202（`text/html`・0バイト、bot 対策の待機）になることがある。
    ページを開いて5秒ほど待ってから fetch し直すと 200（`application/pdf`）になった（2026-10-01）
- PDF は「令和8年M月D日（M月D日時点）」の見出しの**後ろ**に、国家・民間・産油国共同・合計が並ぶ。
  見出しと値の対応を取り違えない。先頭が最新の公表分
- コラム（2.）に使うのは**前月末日時点**の値。月末日の値が無い場合（公表されない日）は直前の日を使い、表に日付を明記する
- `docs/hormuz/index.html` の3か所とハブの1か所（3.）に使うのは、PDF の**先頭（最新の時点）**の値

## 2. 記事を更新する

1. 月次表：前月の「直近速報」行を「M月末（速報）」行に置き換える（前月末値で差し替え）。
   新しい「直近速報」行は置かない（月末値が最新の行になる）。備考欄は数値から読める事実だけを書く
   - 作業日に月末日時点の値がまだ公表されていないときは、直前の日の値で「M月D日（直近速報）」行のままにし、
     グラフ下の注記に「M月末日時点の値は公表後に差し替える」と書く（2026-10-04 は 9/30 時点が未公表で、9/29 時点を使った）。
     **翌月の作業では、まずこの行を月末日時点の値に差し替えてから**、その月の分を追記する
2. 折れ線グラフ（SVG）：点を1つ追加し、x座標を 60〜660 に等間隔で配り直す。
   y座標は `y = 260 − (日数 − 190) × 3.385`。190日を下回ったら軸の目盛りを作り直す
3. グラフ下の注記・`aria-label`・リード文・「まず結論」・メタ description（3か所＋構造化データ）の「現在◯日分」を更新
   - **合計が変わったら、合計から計算した数字も直す。**書き換え後に記事を「日分」で検索し、古い合計を前提にした数字が残っていないかを確かめる
     - 「まず結論」の「約Nか月で◯日分の取り崩し」（◯＝248 − 最新の合計。2026-10-04 に 198→197 で「50日分」が残った）
     - 「6月以降はおおむね横ばい（◯〜◯日分のレンジ）」と、「月ごとの経緯」の当月のレンジ（PDF のその月の全日から最小・最大を取る）
     - 「8月末から◯日分の低下」のような前月末との差、要点ボックスの「民間備蓄の減少（◯→◯日分）」
4. 「月ごとの経緯」に前月の段落を追加。日付には `<span class="at-the-time">` を付ける
5. 要点ボックス・結論を必要に応じて更新
6. 最終更新日（本文の `article-meta` と構造化データ `dateModified`）を作業日にする

## 3. 周辺を追従させる

- `docs/hormuz/index.html` の「石油備蓄の月次推移まとめコラムカード」のサブタイトルと要約
- `docs/articles/index.html` の一覧カードの `idx-lead`
- `docs/sitemap.xml` の該当 URL の `lastmod`
- `docs/hormuz/index.html` の「30秒で全体像」内の特別解説ピル（`📉 石油備蓄推移`）の `data-updated` を、記事の `dateModified` と同じ日付にする。
  これで「◯月更新」の札が30日間表示される
- `docs/hormuz/index.html` の石油備蓄日数3か所（2026-10-01〜。クラウドの日次では PDF を取れないため、ここで更新する）。
  PDF 先頭の最新時点の値で、ハブの1か所とあわせて**4か所を同じ値・同じ時点に揃える**。書式は変えない（`validate_daily.py` が書式で検出している）
  - 地図の「🇯🇵 日本の受入拠点」ポップアップ：`198日分（国家102＋民間92＋産油国共同4、9/27時点）`
  - 精製所表の下の注記：`国家備蓄は約102日分、民間備蓄・産油国共同備蓄を含む合計は約198日分（2026年9月27日時点）`
  - 主要指標の備蓄カード：時点の行 `2026年9月27日時点（速報）`、合計 `198`、内訳 `国家：102日分`・`民間：92日分`・`産油国共同：4日分`
    （国家・民間・産油国共同は PDF の3区分のまま書く。2026-10-03 に地図のポップアップと括り方を揃えた。速報に無い状態の説明（「放出停止」など）は書かない）
  - ハブ `docs/index.html` の「主要な数字」：合計 `<div class="hub-stat-num" id="hub-stockpile">198<span class="hub-stat-unit">日分</span></div>`、
    その下の行 `2026年9月27日時点（速報）・資源エネルギー庁`。**ハブを書き換えた日は `docs/sitemap.xml` の `https://chokepointlab.com/` の `lastmod` も作業日にする**
  - 更新後に `python tools/validate_daily.py` で「石油備蓄日数」の4行が OK になることを確かめる（閾値 40日）

## 4. 書いてはいけないこと

- 速報資料に無い「要因」を推測で書かない（例：国家備蓄が1日分減った理由）。
  政策の動きを書く場合は、Web 検索で確認した一次資料・報道に限り、出典を本文に示す
- `docs/hormuz/index.html` と `docs/index.html` で触るのは 3. に挙げた箇所だけ。ほかの箇所にある備蓄日数の記載（速報・ニュース本文など、その日の報道を引いたもの）は書き換えない
