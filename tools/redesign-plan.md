# ホルムズ海峡危機マップ 大改造計画

策定: 2026-09-04 JST
目標: サイトの見た目・可読性・コンテンツ構成・回遊性を段階的に大改善する

---

## 0. 大原則（順序を決めているルール）

1. **HTML構造の変更はドメイン移行の「前」、CSS見た目の変更は「後」**
   - 移行直後は検索評価の再計算が走る。同時にHTML構造を変えると順位変動の原因が切り分け不能になる
   - CSS（色・文字サイズ・カラム組）は検索評価に影響しないため移行後で安全
2. **`tools/migrate-domain.sh` はホスト名のリテラル置換のみ。ファイルパスを変えない限り改修と衝突しない**
   - CLAUDE.md「パス変更とホスト名置換を同一コミットに混ぜない」に従う
3. **フェーズをまたぐコミットを作らない。** 各フェーズは独立して revert できる状態を保つ

## 2. フェーズ0：CSS基盤整備（前提工事）

### 目的

`docs/index.html` は `:root` を1つも持たず、`font-size` が 447箇所（うちインライン `style` が 306箇所）に散在している。
この状態では「文字を少し大きく」という変更が447箇所の手作業になるため、先に一元化する。

### 実測された問題（2026-09-04）

- `:root` 定義が存在しない（`design-system.md` のトークンは未実装）
- `font-size` rem指定の分布: `0.75rem`×63 / `0.72rem`×62 / `0.78rem`×40 / `0.8rem`×29 / `0.85rem`×21
  - PC（16px基準）では 11〜12px 相当。可読下限 14px を大きく下回る
  - スマホは `@media (max-width:768px){html{font-size:18px}}` に救われているが、PC には救済がない
- `0.65〜0.78rem` の間に11段階が密集。設計ではなく偶然の集積
- px直指定が41箇所（6px〜26px）。rem基準の底上げが効かない
- メディアクエリのブレークポイントが 480 / 600 / 640 / 768 / 860px と5種混在（21箇所）

### 0a：トークン定義＋ブレークポイント統一（見た目不変）

- `:root` にタイポグラフィ・スペーシング・カラーのトークンを定義
- ブレークポイントを **768px / 1024px の2点**に統一（既存の 480/600/640/860 を吸収）
- **成功条件: 表示差分が出ないこと**

### 0b：既存値をトークンへ置換（段階統合）

- 密集した11段階を5段階へマッピング
- px直指定を rem/clamp へ（地図マーカー等、意図的な px は除外）
- 最小値を `0.875rem`（14px）に引き上げ、`0.7rem` 台を全廃

### 禁止事項

- `@media (max-width:768px){html{font-size:18px}}` は削除・変更しない（CLAUDE.md 絶対ルール）
- コメントアウトタイトル `<!-- xxxx -->` を変更しない
- 原本を直接 `open(path,"w")` しない。一時ファイル＋`os.replace()`
- `sed -i` を CRLF ファイルに使わない

## 3. フェーズ1：コンテンツ整理（A案・3層ピラミッド型）

### 現状の重複

同一情報が最大4箇所に出ている:
`30秒サマリー` / `情勢カード×3` / `全ルート現況サマリー`（長大な1段落）/ `速報インシデント` / `最新ニュース`

### A案の構造

情報を「深さ」で階層化し、重複を「要約→詳細」の正当な関係に変える。

```
第1層 いま何が起きているか  ← 30秒サマリー＋情勢カード（統合）
第2層 どう影響するか        ← 地図・ルート表・シナリオ・市場
第3層 なぜそうなのか        ← コラム・全文・アーカイブ・出典
```

統合対象:
- 情勢カード → 30秒カラムへ吸収
- 「全ルート現況サマリー」の長文 → ルート表の各行へ分解

### 1a / 1b の分割（移行スケジュールの都合）

| | 内容 | 時期 | リスク |
|---|---|---|---|
| **1a** | セクション名の `h2`/`h3` タグ化のみ | ドメイン移行**前** | 低（見た目ほぼ不変） |
| **1b** | セクション統合・再配置（A案本体） | ドメイン移行**後** | 中 |

1a を移行前に行う理由: 現状の見出しタグは `h1`×1・`h2`×3 のみで、
セクション名はすべて `div`/`span`。この状態で移行すると誤った構造のまま評価が引き継がれる。
タグ差し替えだけで SEO 効果の大半を確保でき、リスクが低い。

## 4. フェーズ2：レイアウト・文字サイズ最適化

### カラム設計

| セクション | PC(≥1024) | タブレット(768-1023) | スマホ(<768) |
|---|---|---|---|
| 30秒サマリー | 3列 | 2列 | 1列 |
| 情勢カード | 3列 | 2列 | 1列 |
| シナリオA〜D | 2列×2 | 2列×2 | 1列 |
| 特別解説コラム | 3列グリッド | 2列 | 1列 |
| ニュース／出典ログ | 2列 | 2列 | 1列 |
| 長文解説（コラム本文） | 1列＋`max-width:70ch` | 同左 | 1列 |
| ルート表 | 全幅テーブル | 全幅 | 横スクロール（現状維持） |

**長文は多段組にしない。** 新聞の段組は「行長を短くする」のが目的であり、
Web では `max-width: 70ch`（全角約35字）で中央寄せするのが正解。
現状の「横長でだらーっと読みにくい」は、カラム数ではなく行長の問題
（コンテナ `max-width:1400px` の1カラムで全角90字近くになっている）。

### タイポグラフィ（フェーズ0のトークン値を書き換えるだけで適用される）

```css
:root{
  --fs-body:    clamp(1.0rem, 0.95rem + 0.3vw, 1.125rem);
  --fs-lead:    clamp(1.05rem, 1rem + 0.4vw, 1.25rem);
  --fs-caption: clamp(0.875rem, 0.85rem + 0.15vw, 0.95rem);
  --fs-h2:      clamp(1.35rem, 1.1rem + 1.2vw, 2rem);
  --fs-h3:      clamp(1.1rem, 1rem + 0.6vw, 1.4rem);
  --lh-body: 1.75;
}
```
