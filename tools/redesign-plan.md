## 0. 大原則（順序を決めているルール）

1. **HTML構造の変更はドメイン移行の「前」、CSS見た目の変更は「後」**
   - 移行直後は検索評価の再計算が走る。同時にHTML構造を変えると順位変動の原因が切り分け不能になる
   - CSS（色・文字サイズ・カラム組）は検索評価に影響しないため移行後で安全
2. **`tools/migrate-domain.sh` はホスト名のリテラル置換のみ。ファイルパスを変えない限り改修と衝突しない**
   - CLAUDE.md「パス変更とホスト名置換を同一コミットに混ぜない」に従う
3. **フェーズをまたぐコミットを作らない。** 各フェーズは独立して revert できる状態を保つ

### 凍結期間の定義（2026-09-13 明文化）

策定時（2026-09-04）は表に「凍結・安定確認」と1行書いただけで**中身を定義していなかった**。
凍結中に「これは触ってよいのか」で迷うため、ここに定める。

#### 目的

1. **移行後の変動の原因を1つに絞る。** 大原則1のとおり、移行直後は検索評価の再計算が走る。
   直前まで手を入れていると、順位やアクセスが動いたときに「移行のせい」か
   「自分が入れた変更のせい」かを区別できなくなる。
2. **移行前の正常な状態を確定させる。** 移行後に突き合わせるための基準値を取る期間でもある。

#### 止めるもの（サイトの「形」を変える作業）

- HTML 構造の変更（セクションの追加・削除・並べ替え、タグの変更）
- CSS の変更（フェーズ2は元々移行後）
- ファイルの移動・リネーム・パス変更
- `<title>` / `canonical` / `og:` / `twitter:` / JSON-LD などメタ情報の変更
- 新規ページの追加、リンク構造の変更
- `sitemap.xml` の構造変更（日次更新に伴う `lastmod` の更新は除く）

#### 続けるもの

- **日次更新（`/daily-site-update`）。凍結の対象外。**
  §10 の「コンテンツの日常更新は停止せず継続する」に従う。
  既存の器に中身を入れ替える作業であり、移行の切り分けを濁さない。
- 検証・実測・記録（`PROJECT_CONTEXT.md`・引き継ぎノート・本ファイルの更新）
- 移行の準備作業のうち**本番を変えないもの**（`tools/migrate-domain.sh --dry-run` など）

**線引きは「サイトの形を変えるか、中身を差し替えるか」。**

#### 凍結中に取る基準値（移行後に突き合わせる）

- 全ページの HTTP ステータス（トップ・法務6枚・`/infographic/`・`/archive/`・`/articles/*`）
- ブラウザのコンソールエラー件数（0であること）
- 横スクロールの有無（1280px / 375px の `document.documentElement.scrollWidth`）
- `sitemap.xml` の URL 一覧と `robots.txt` の内容
- 主要ページの `canonical` / `og:url` の現在値（移行スクリプトの置換対象）

#### 例外（なし・2026-09-13 に撤回）

~~`@chokepointlab` の本運用開始と X リンクの差し替え（§11-12(C)）は 9/18 の移行と同時~~
→ **2026-09-13 に期限を撤回**し、`@chokepointlab` の準備ができ次第、移行とは別日に行うことにした
（`tools/migration-runbook.md` 手順8）。したがって凍結期間の例外は無い。

- X 上の作業（プロフィール整備・投稿）はサイトに触れないので、凍結中でも行ってよい
- **サイトの X リンク差し替えは HTML の変更なので、凍結中（9/15〜9/17）は行わない。**
  行うときは移行コミットとも日次更新とも別の独立コミットにする
- 記録上「フッターの X リンク」と呼んでいるが、実際の位置はページ上部（30秒カードの上）

#### 凍結を破る場合

公開中の記述の誤り（訂正記録の対象になるもの）や、読者に見える不具合が見つかった場合は
凍結より優先して直す。ただし**独立したコミットにし、何を触ったかを本ファイルに記録する**。
移行後に変動を見るとき、凍結が破られた事実を知らないと切り分けを誤る。

## 2. フェーズ0：CSS基盤整備（前提工事）— 完了（2026-09-04）

### 目的

`docs/index.html` は `:root` を1つも持たず、`font-size` が 447箇所（うちインライン `style` が 306箇所）に散在している。
この状態では「文字を少し大きく」という変更が447箇所の手作業になるため、先に一元化する。

### 実測された問題（2026-09-04）

- `:root` 定義が存在しない（`tools/design-system.md` のトークンは未実装）
- `font-size` rem指定の分布: `0.75rem`×63 / `0.72rem`×62 / `0.78rem`×40 / `0.8rem`×29 / `0.85rem`×21
  - PC（16px基準）では 11〜12px 相当。可読下限 14px を大きく下回る
  - スマホは `@media (max-width:768px){html{font-size:18px}}` に救われているが、PC には救済がない
- `0.65〜0.78rem` の間に11段階が密集。設計ではなく偶然の集積
- px直指定が41箇所（6px〜26px）。rem基準の底上げが効かない
- メディアクエリのブレークポイントが 480 / 600 / 640 / 768 / 860px と5種混在（21箇所）

### 0a：トークン定義＋ブレークポイント統一（見た目不変）

- `:root` にタイポグラフィ・スペーシング・カラーのトークンを定義
- ブレークポイントを **768px / 1024px の2点**に統一（既存の 480/600/640/860 を吸収）
- **成功条件: 表示差分が出ないこと**

### 0b：既存値をトークンへ置換（段階統合）

- 密集した11段階を5段階へマッピング
- px直指定を rem/clamp へ（地図マーカー等、意図的な px は除外）
- 最小値を `0.875rem`（14px）に引き上げ、`0.7rem` 台を全廃

### 検証環境の制約（2026-09-04 に実際に誤判定した）

ローカル `file://` では**画像も iframe も読み込まれない**。
このため画像の代わりに `alt` テキストが展開され、実サイトには存在しない
はみ出しが観測される。実際に 375px で「横スクロール82px」と誤検出し、
不要な修正を加えかけた（実画像は 1672x941 で表示幅128px、はみ出しは発生しない）。

**レイアウトの最終確認は push 後の GitHub Pages で行うこと。**

### 禁止事項

- `@media (max-width:768px){html{font-size:18px}}` は削除・変更しない（CLAUDE.md 絶対ルール）
- コメントアウトタイトル `<!-- xxxx -->` を変更しない
- 原本を直接 `open(path,"w")` しない。一時ファイル＋`os.replace()`
- `sed -i` を CRLF ファイルに使わない

## 3. フェーズ1：コンテンツ整理（A案・3層ピラミッド型）

### 現状の重複

同一情報が最大4箇所に出ている:
`30秒サマリー` / `情勢カード×3` / `全ルート現況サマリー`（長大な1段落）/ `速報インシデント` / `最新ニュース`

### A案の構造

情報を「深さ」で階層化し、重複を「要約→詳細」の正当な関係に変える。

```
第1層 いま何が起きているか  ← 30秒サマリー＋情勢カード（統合）
第2層 どう影響するか        ← 地図・ルート表・シナリオ・市場
第3層 なぜそうなのか        ← コラム・全文・アーカイブ・出典
```

統合対象:
- 情勢カード → 30秒カラムへ吸収
- 「全ルート現況サマリー」の長文 → ルート表の各行へ分解

### 1a / 1b の分割（移行スケジュールの都合）

| | 内容 | 時期 | リスク |
|---|---|---|---|
| **1a** | セクション名の `h2`/`h3` タグ化のみ | ドメイン移行**前** | 低（見た目ほぼ不変） |
| **1b** | セクション統合・再配置（A案本体） | ~~ドメイン移行**後**~~ → **移行前**（2026-09-06 決定） | 中 |

1a を移行前に行う理由: 現状の見出しタグは `h1`×1・`h2`×3 のみで、
セクション名はすべて `div`/`span`。この状態で移行すると誤った構造のまま評価が引き継がれる。
タグ差し替えだけで SEO 効果の大半を確保でき、リスクが低い。

### フェーズ1b 実施結果（2026-09-12）

移行まで1週間を切っており、統合は日次更新スクリプト（S03・S08.5）の作り直しを伴うため。

#### 1b-0：前提工事（`d1221f0`・表示不変）

- `docs/index.html:1543`「ルートC・アラスカ」の `<a>` が閉じられておらず、内側に
  「西アフリカ・南米調達」の `<a>` が入れ子になっていた（`<a>` の入れ子は不正）。
  ここで生じた1段のずれが以降の `</div>` を繰り上げ、**ジャンプ帯・特別解説グループ・
  解説インフォグラフィックの3ブロックが30秒カードの枠外へ押し出されていた**

  第10版の「div の開閉差 -13」の正体。ブラウザは無視するため表示は正常だった
- **方針：見た目は変えず、ソースを実 DOM に一致させた。**
  「カードに何を囲わせるか」は意匠の判断としてフェーズ2へ送る

#### 1b-1：並べ替え（`0e4b0fd`）

- 層ラベルは `div.layer-band`（`h1`/`h2`/`h3` を使わない）。上記 §8 の決定に従う

- **依存関係**：Leaflet 地図スクリプト（`<script>`・パース時に即時実行、`#map` と

  S09 の間に挟まれている」という**位置の説明は両方とも失効**したので更新した

  それぞれ手で追記しないと表示されない（どちらもキーをコードに直書きしている）

### 既知の不整合（依頼6で解消すべき点）

1. **`updated` が「2026年5月4日 JST」のまま**（2026-09-04 時点で約4か月前）。

2. **`old` と `D` は hormuz-map 側では JSON を見ていない。**
